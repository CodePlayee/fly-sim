# flySim — Web3D 模拟飞行（免费全球地形，无需 token）

用 Web3D 技术尽量还原《微软模拟飞行》的核心体验：**真实全球 3D 地形、卫星影像、大气、随真实时间变化的太阳/月亮光照**，支持从 3 个世界知名国际机场起降。

> **完全免费**：不需要任何 token / API key / 登录。

## 技术方案

| 模块 | 方案 | 是否需 key |
|------|------|-----------|
| 渲染引擎 | **three.js**（统一 3D 场景：飞机与地形同场景） | 否 |
| 全球地形 mesh | **geo-three** + 自定义 provider 喂 AWS Terrarium DEM | 否 |
| 卫星影像贴图 | **Esri World Imagery** | 否 |
| 天空大气 | three.js **Sky**（Preetham） | 否 |
| 太阳/月亮位置与光照 | **SunCalc**（纯本地天文计算） | 否 |
| 夜间城市灯网 | **OpenFreeMap 矢量瓦片**（OSM 路网/建筑/跑道，MVT） | 否 |

飞机与地形渲染在**同一个 three.js 场景**、共享相机与深度缓冲，因此离地高度(AGL)、
碰撞、近地警告与遮挡都**所见即所得**。geo-three 用四叉树 LOD 流式加载全球真实高程，
高程瓦片用 Terrarium 编码（在 provider 内转码为 geo-three 期望的 Mapbox RGB）。

## 运行

```bash
npm install
npm run dev      # http://127.0.0.1:5273/
npm run shot     # 生成 shots/*.png 截图验证
npm run bench    # 首屏耗时基准（航线列表 / 地形各 LOD 层级就绪时间）
```

### 操作

| 按键 | 功能 |
|------|------|
| ↑ / ↓ | 俯仰：↑ 拉杆抬头 / ↓ 推杆低头（升降舵同步上下） |
| ← / → | 横滚：← 左滚 / → 右滚（副翼差动） |
| W / S | 加/减油门 |
| A / D | 偏航：A 左 / D 右（方向舵左右） |
| V | 切换追尾/座舱/自由视角 |

右上角控制区还有 **⏩ 速率** 按钮：循环切换时间加速倍率 `1× → 2× → 5× → 10× → 25× → 50× → 100×`，
用于远程航线快速推进。物理用**子步进**积分（把加速后的时长切成 ≤20ms 的小步逐步计算），
高倍率下升力/姿态仍稳定不发散。

起飞：W 加满油门，空速达约 117 kt 后拉 ↑ 抬轮。右上角可切换机场、拖动滑块改当地时间看昼夜光照、或点"真实当前时间"。

## 全球机场 + 在线搜索

除内置的 3 个预设机场外，**可在线搜索全球任意主要机场**作为出发/目的地（仍**无需 token / API key**）：

- 进入航班选择界面或点 HUD 右上「✈ 换机场」，在出发搜索框输入**城市 / 国家 / IATA / ICAO**（如 `Tokyo` / `NRT` / `悉尼` / `YSSY`）。
- 选定出发机场后，在线拉取其**真实航线**作为目的地列表（含运营航司、距离）。
- 任意搜索到的机场都能**作为出发点起飞**：自动补齐真实**跑道航向**、**标高**、**时区**。

数据来自公开数据源（运行时按需 fetch、会话内缓存，均开放 CORS）：

| 数据 | 来源 | 用途 |
|------|------|------|
| 机场库 | OpenFlights `airports.dat` | 坐标 / 时区 / 标高 |
| 跑道航向 | OurAirports `runways.csv` | `le_heading_degT`（按 ICAO 关联） |
| 航线 + 航司 | OpenFlights `routes.dat` / `airlines.dat` | 目的地与运营航司 |

> **离线兜底**：在线请求失败时自动回退到内置 3 机场及其预生成航线（`src/routes.js`），
> 功能不中断。切换出发机场时场景原点（origin）会重设并重定位地形 mapView，
> 保证全球任意机场都无浮点抖动。

国家 / IATA 代码搜索。

生成 `src/routes.js` 打包进项目，**运行时无需联网**（契合本项目无 token 原则）。

## 光照说明

SunCalc 按机场真实经纬度 + 时刻计算太阳/月亮的方位角与高度角，驱动：
- 天空与地平线大气配色（白天蓝天 / 黄昏金光 / 暮光蓝调 / 夜晚暗蓝）
- 山体阴影的照射方向（随太阳/夜间月亮方位旋转）
- 卫星影像整体明暗 + 夜间压暗叠层

经像素亮度实测，昼夜单调正确：正午最亮 → 黄昏 → 夜晚最暗。

### 夜空与城市灯光

为避免夜间"天地全黑"，专门做了天空与地面两套夜景增强：

**天空（`skybox.js`）**——叠加在 three.js Sky 大气之上，按夜间因子淡入：
- **星空**：~2200 颗加性混合星点（色温/亮度各异，少量亮星更大），夜间淡入、满月时略减弱
- **月亮**：暖白月面圆盘（含月海斑纹）+ 柔和光晕，按 SunCalc 真实月亮方位/高度定位，**仅地平线以上可见**，亮度随月相（`moonFraction`）变化
- **地平线暮光渐变**：傍晚地平线呈金橙→暖红→深蓝的逼真色带，深夜转为纯深蓝
- 关键：月亮/星空在 `fog.far` 之外，须 `fog:false`，否则被夜雾染黑

**地面（`cityLights.js`）**——夜间在城区叠加暖色加性发光精灵模拟万家灯火：
- 城市种子来自内置主要城市表（~100 个全球枢纽）+ 运行时机场注册表
- 仅实例化当前机场 420km 内的城市，每城按规模撒 12~55 个灯点成簇，**锚定地形高度**
- 白天全灭、暮光起淡入，带极轻微闪烁（模拟大气视宁度）；受雾影响使远处灯火自然隐入夜色
- 灯光精灵 `depthTest:false`（同月亮/星空），辉光始终穿透显示，**不被地形起伏遮挡**
- 同时上调夜间环境光，让地形不再纯黑

> 此前夜间过黑的主因之一是 HUD 有个最高 0.55 不透明度的**纯黑 DOM 压暗层**，会把星空/月亮/城市灯一起压死；现已大幅削弱（≤0.18），真实暗部交由天空渐变 + 地面光照 + 雾负责。

### 真实 OSM 城市灯网（点/线/面 + AGL LOD）

`cityLights.js` 的程序化光晕只是"兜底"。**夜间全程显示**真实城市灯网（`cityNetwork.js`），
用**真实 OSM 矢量瓦片**构建夜航俯瞰般的城市灯（如参考图：道路连绵成
发光线、密集建筑光点、机场跑道亮带、河流暗带）：

- **数据源**：OpenFreeMap 矢量瓦片（`tiles.openfreemap.org`，**免费、无 token、CORS:\***，MVT 格式，zoom 0–14）
- **解码**：`@mapbox/vector-tile` + `pbf`，提取 `transportation`/`building`/`aeroway`/`water` 图层
- **构建**（`src/providers/VectorTileSource.js` 取数解码 → `src/cityNetwork.js` 建几何）：
  - **道路** → 加性发光 `LineSegments`（主干亮金橙、次级暖橙），构成灯网骨架
  - **建筑** → footprint 质心 `Points` 暖光点，构成城区面状辉光主体
  - **跑道/滑行道** → 冷白 `LineSegments` 亮带（对比城区暖色）
  - **水体** → 暗色 `Mesh` 遮罩，增强对比
  - 灯贴地略上方，经纬度经 `geoToWorld` 与 geo-three 地形**精确对齐**；`depthTest:true`
    使**飞机机身正确遮挡其下方灯光**（不会有灯光穿透压在机身之上）
- **AGL LOD**（随飞机离地高度自适应：低空用稍粗 zoom + 大 radius 覆盖远视距，
  地平线可达数十 km，避免视野中出现明显的"未加载边界"）：

  | AGL | 瓦片 zoom | 范围 | 覆盖 | 视觉 |
  |-----|----------|------|------|------|
  | <1200m | z14 | 9×9 | ~19km | 精细：全路网+建筑点+跑道 |
  | 1200–4000m | z13 | 11×11 | ~47km | 中等：主干路+建筑 |
  | 4000–8000m | z12 | 11×11 | ~93km | 概略：主干路+建筑簇 |
  | >8000m | z11 | 13×13 | 更广 | 高空：仅主干路网骨架 |

- **节流/缓存/卸载**：每 ~400ms 重算所需瓦片集，LRU 缓存 + 并发上限；移出范围即
  `dispose` 释放显存。白天整体透明度平滑渐出并卸载全部瓦片。
- **航线预加载**（航线固定、飞行路径可预测）：
  - **前向偏置**——可见窗口沿当前航向推前（偏置量随地速增大），让前方先于正下方建好；
  - **走廊预热**——沿航向在前方约 45 秒航程（且不少于可见半径+5 个瓦片）的走廊提前
    `fetch`+解码瓦片进缓存（只热缓存、不建几何），待飞机临近进入可见集时即为即时命中，
    `buildTile` 不再等网络，**消除"临近才加载灯网"的突兀**。前视距离按瓦片地面尺寸自适应，
    高空(瓦片大、速度快)与低空(瓦片小)都有足够提前量。
- **兜底**：瓦片加载失败/断网 → 自动回退 `cityLights.js` 暖色光晕，不中断。

## 首屏加载优化

首屏原本很慢（实测：航线列表 1.2s，机场脚下地形达到 z12 要 **57s**、z14 要 **66s**，
过渡层则固定压满 18s）。定位到五个根因并逐项修复，现在航线列表 **~190ms**、
地形 z12 **~7s**、点「开始飞行」到过渡层消失 **~1.7s**（挑航班的那几秒里地形已加载完）：

| 根因 | 说明 | 修复 |
|------|------|------|
| **航线数据先等网络** | 启动即 `await` 三份跨域 CSV（airports/routes/airlines，共 7.5MB 原始 / 860KB gzip），内置 `src/routes.js` 只当失败兜底 | `flightSelect.js` 改为**离线优先、在线增补**：内置机场同步渲染，在线数据到达后按 IATA 复位选中项无缝替换 |
| **geo-three 逐级串行瀑布**（主因） | `MapNode.subdivide()` 要求 `parentNode.nodesLoaded === 4`，即父节点的 4 个兄弟瓦片全部下载解码完才允许下一级细分；且只在 `onBeforeRender` 触发，每级还占一帧。从 z0 到 z14 = **14 个严格串行的网络波次** | 新增 `terrainWarmup.js`，直接调 `createChildNodes()` 沿目标机场链路建树，绕过该门槛，**14 个 RTT 压成 ~1 个**；页面一打开就预热（用户还在选航班时地形已在加载） |
| **每张瓦片内部又串行一次** | `MapHeightNode.initialize()` 是 `await loadData()` 然后 `await loadHeightGeometry()`——影像与高程互不依赖却吃 **2 个串行 RTT**，把总时长直接翻倍 | `world.js` 顶部打补丁改成 `Promise.all` 并行（首屏过渡层实测 5.8s → 1.7s） |
| **就绪判定恒为假** | geo-three 的 `MapView.raycast()` 无条件 `return false`，而 three ≥0.164 把 false 解读为「不要向子节点递归」→ `intersectObject(mapView,true)` **永远返回空**，过渡层只能靠 `MAX_MS=18000` 兜底消失，与地形实际速度无关 | 改从 `mapView.children` 起算；并显式校验 `heightLoaded/textureLoaded` + 整条祖先链 `visible`（three 的 raycast 不过滤 `visible`，占位节点会造成误判） |
| **HTTP/1.1 单 origin 6 连接** | Esri 与 S3 都只支持 HTTP/1.1，上百张瓦片被切成十几个串行波次；换机场时旧机场的几百个在途请求还会把新机场的关键路径挤到队尾 | DEM 走 `providers/demHosts.js` 的 **4 个等价 S3 origin** 确定性分片（同瓦片恒定同主机以复用缓存）；首屏暂停 LODFrustum 把连接额度让给关键路径（揭幕后或 20s 兜底恢复）；换机场时 `provider.abortPending()` 取消旧机场在途请求（换机场实测 18.9s → 9.4s） |

此外过渡层改为**分阶段揭幕**：脚下出现 ≥z12 瓦片即渐隐（`REVEAL_LEVEL`），
更精细的 z13~z15 在飞行中后台继续细化，不必干等。
预热也分两阶段：正下方链路立即建（关键路径），周边 3×3 圈延到 `requestIdleCallback` 再建。

> 剩余瓶颈：Esri 影像只有单一 origin（无可用备选主机）且不支持 HTTP/2，6 条连接
> 是硬上限。要再快需减少链路瓦片数，或让低层级换用另一 origin 的免费全球影像分担。
> 用 `npm run bench` 可复现测量（网络抖动较大，建议多跑几轮取中位数）。

## 机场跑道压平

全球 DEM 精度有限（Terrarium z14/z15 约 10~30m/px），而 geo-three 每块瓦片只把
256×256 高程**降采样成 17×17 个顶点**（z14 下约 150m 一个采样点），跑道沿线的地形
mesh 因此是起伏的；而 `aircraft.js` 的触地判定用的是常数 `fieldElevation + 3`
（机场标高），两者对不上——滑跑中只要某处地形高过机场标高，**飞机就会被埋进地面**。

> 实测因斯布鲁克 LOWI（标高 581m）：起飞方向 +2500~3000m 处地形 mesh 高达 **599.7m**，
> 比飞机的 584.0m 高出近 16m，23 个采样点里有 3 个把飞机埋住。

注意「让飞机改为跟随 `terrain.elevationAt`」**解决不了**：那是 256×256 双线性采样，
与 geo-three 的 17×17 最近邻降采样是两个不同的值，差异可达数十米
（`cityNetwork.js` 的 `LIGHT_LIFT` 正是为绕开这个差异而存在）。

`runwayFlatten.js` 采用真实模拟器的做法——在机场周围把高程强制压到机场标高：

| 距机场中心 | 高程 |
|---|---|
| ≤ 2200m（`FLAT_RADIUS`） | 恒等于 `airport.elevation`（完全平，覆盖最长跑道的半长） |
| 2200 ~ 6000m（`BLEND_RADIUS`） | smoothstep 混合，避免出现环形悬崖 |
| ≥ 6000m | 原始高程，真实地貌不受影响 |

关键是它**同时作用于两条链路**，使二者在机场区域严格相等、误差为 0：
- `TerrariumHeightProvider`：转码时写进瓦片像素 → 决定 geo-three 的**视觉 mesh**
- `terrain.js elevationAt`：输出端修正 → 决定 **AGL / GPWS** 读数

> ⚠️ 压平区必须在该机场瓦片被加载**之前**注册（`main.js` 在启动时、以及 `goToAirport`
> 里先于 `warmupTerrain` 调用 `registerFlatten`），否则已解码缓存的瓦片不会重新压平。
> 注册表是累积的，来回切换机场不会失效。低于 `FLATTEN_MIN_ZOOM=10` 的瓦片跳过压平
> （顶点间距达数 km，压平无视觉意义，却要为链路上每一级白跑 65536 次逐像素计算）。

压平后同一条跑道带恒为 581.0m，飞机 584.0m，**0/23 采样点穿模**。

## 瓦片失败与黑色矩形块

geo-three 对瓦片加载失败的处理是**一次性**的：

```js
catch { this.material.map = MapNode.defaultTexture; }   // MapNode.loadData
MapNode.defaultTexture = TextureUtils.createFillTexture(); // 默认 '#000000'，1×1 纯黑
```

即**任何一次加载失败，那块地形就永久变成黑色矩形**，此后不会再重试。

而首屏优化引入的 `abortPending()`（换机场时取消旧机场在途请求、把 HTTP/1.1 仅有的
6 条连接让给新机场）会让几百个请求以 `net::ERR_ABORTED` 结束 —— 实测**一次换机场
就制造 200 个黑块**。诊断佐证：全程不换机场时 abort 数为 **0**、且 HTTP 状态码里
**没有任何非 200**（不是限流、不是 404，纯粹是自己取消的）。

`providers/RetryingImageLoader.js` 重新定义了两种失败语义：

| 场景 | 行为 |
|------|------|
| **abort**（换机场让路） | 中止下载立刻释放连接，但 Promise **保持 pending**，1.5s 后自动重发 —— geo-three 永远等到真实数据，不会走进黑色兜底 |
| **真实网络错误** | 指数退避重试 2 次（400ms / 800ms），耗尽才 reject |

修复后：`Failed to load node tile data` 告警 **200 次 → 0 次**，
连续换机场 KSFO→LFPG→VHHH 后**黑纹理 0、画面可见黑块 0**，且成功瓦片数不降反增。

## 结构

```
src/
  main.js          # 入口：统一场景编排、相机跟随、输入、主循环、对外 API
```

## 飞机模型

`boeing737.js` 用纯程序化方式（圆柱机身 + 椭球机头 + 后掠机翼 + 翼梢小翼 +
吊挂发动机 + 后掠垂尾，带蓝色涂装），**不依赖任何外部模型文件**，
生成一架可辨识的 737 风格客机。

**可动部件（随操纵实时动画）**：副翼（随滚转差动偏转）、襟翼（起降构型放下）、
升降舵（随俯仰）、方向舵（随偏航/转弯）、发动机风扇（随油门旋转）。机翼后缘与
**垂尾后缘**的操纵面均**嵌入固定翼面的凹槽**（铰链在凹槽前沿、后端齐平真后缘），
俯视下后缘分段精细、偏转时凹槽连续露出（不再是悬浮的碎块）；主翼下表面带 737
标志性的**襟翼滑轨整流罩**（flap track fairings 鼓包）。各舵面由
`group.userData.controls` 暴露，叠层每帧按飞行状态平滑驱动。

> **左右对称约定**：左右翼面/平尾用 `scale.y=±1` 镜像安装（`mountWing`），上反角
> 随侧别翻转以保证两翼同向上扬。经数值探针实测：镜像 `scale.y=-1` **不会**翻转
> 子组 `rotation.y` 的竖直方向，故「左右同号=同步偏转、左右反号=差动」。据此：
> **副翼**取反号→差动（横滚），**升降舵**取同号→同步上下（俯仰），方向舵绕竖轴左右（偏航）。

渲染采用**独立透明 Three.js 画布叠加在地图前景**的方案：追尾/座舱视角下飞机
始终是最近物体，应永远在前景，无需与地形做深度合成或地理投影，更稳健。
模型受光与 SunCalc 计算的太阳方位/高度同步。

## 外部灯光（夜间开启）

`boeing737.js` 的 `buildExteriorLights` 按真实客机布置外部灯（发光球 core +
加法混合光晕 halo；着陆灯另含 SpotLight 前射光锥），由 `aircraftModel` 每帧驱动，
**白天全灭、暮光起（太阳高度角 < −3°）开启**：

| 灯种 | 位置 | 颜色 | 时机 |
|------|------|------|------|
| 航行灯 nav | 左翼尖 / 右翼尖 / 尾椎 | 红 / 绿 / 白 | 夜间常亮 |
| 防撞信标 beacon | 机身顶 + 机腹 | 红 | 夜间脉冲闪 |
| 频闪 strobe | 两翼尖 + 尾椎 | 白 | 夜间高频双闪 |
| 着陆/滑行灯 landing | 翼根前缘×2 + 机头 | 白 | 夜间且地面 / 低空(<450m AGL) |

昼夜判定来自 `main.js` 缓存的 `currentSunAltDeg`（SunCalc 实时计算），逐帧以
`{night,tMs,agl,onGround}` 传入 `aircraftModel.update`。检视：`scripts/inspect_lights.*`。

## 飞行动力学

`aircraft.js` 是一套**点质量 + 姿态的简化 6-DOF**飞行模型（"街机增强"档），
用力/力矩积分而非运动学衰减，真实感来源是**带攻角(AoA)的升力曲线**：

- 升力 `L = ½ρV²S·CL(α)`，CL 随攻角线性增长，**超过失速角(16°)后骤降**
- 阻力极曲线 `CD = CD0 + k·CL²`（含诱导阻力），随高度的空气密度衰减
- 纵向：`dV/dt = (推力−阻力)/m − g·sinγ`（速度↔高度能量耦合）
- 法向：航迹角 γ 由升力与重力分量积分；**协调转弯**由坡度的水平升力分量改变航向
- **失速**：升降舵失效 + 自然低头力矩，自动趋向改出（机头下俯减小攻角）
- **自动回稳**（按需）：松杆后滚转归零、俯仰趋向当前速度的平飞配平；
  配平**坡度自适应**，转弯时自动多拉杆维持高度
- HUD 显示实时**过载(g)**与**失速告警**

> 为何不用通用物理引擎：Rapier/Cannon/Ammo 等只做刚体/碰撞，**不含空气动力学**
> （真实感的全部来源仍需自写）；且本项目在地理坐标（经纬度+大圆推进）中运动，
> 与引擎的局部笛卡尔空间存在坐标系阻抗。自研在现有框架内零依赖、可逐项调参。

## 近地警告系统（GPWS）

`gpws.js` 模拟真实飞机的近地警告。它沿**预测航迹**（按当前航向、地速、垂直
速度向前外推 30 秒）逐点用 `map.queryTerrainElevation` 采样地形高度，计算预测
路径相对地形的最小离地余量与撞地剩余时间，分级告警：

| 等级 | 触发条件 | 显示 |
|------|---------|------|
| 安全 | 预测路径离地 > 150m | 无 |
| 警戒 caution | 预测离地 ≤ 150m 或撞地 ≤ 22s | 黄色 **"TERRAIN AHEAD"** 横幅 + 黄色屏幕边缘闪烁 |
| 警告 warning | 预测离地 ≤ 60m 或撞地 ≤ 12s | 红色 **"PULL UP ▲"** 横幅 + 红色屏幕边缘急闪 |

HUD 仪表盘新增"离地(AGL)"实时读数，并随告警等级变色。关键在于它是**预测式**
的：即使当前正下方还有余量，只要前方航迹会撞山就会提前告警。

## 地形加载过渡层

选定航线起飞后，全球真实地形瓦片（geo-three 流式 LOD）需要时间加载。`loadingMap.js`
在此期间覆盖一张**全屏半透明 2D 航图**：

- **大圆航线**（品红流动虚线）+ 沿线滑行的小飞机；经纬网格背景
- **出发/目的地机场标记**（黄/蓝光晕点 + IATA 代码 + 城市名）
- 顶部 **`出发 ✈──→ 目的地` + 大圆距离 km**，底部不确定进度条
- 经度去环绕投影，跨太平洋等远程航线正确显示**北弯大圆弧**

地形就绪后整层**渐隐消失**（就绪判定用无全局超时的向下 raycast，确保中途换机场也能正确触发）。

## 导航小地图（ND）

`minimap.js` 在右下角绘制一个圆形导航显示（北朝上）：
- **已飞航迹**（绿色线）——实时记录飞行路径
- **机场**（黄色=出发机场，蓝色=其它；超出量程时夹到边缘作方向指示）
- **到目标的航线**（品红虚线）+ 目标符号，左上角显示**方位 / 相对转向(左/右N°) / 距离**
- **本机符号**（中心三角，按航向旋转）+ 航向矢量
- **距离环 + 量程自适应**（1–10000km，保证出发机场与目标都在画面内）

**航点导航**：默认目标为最近的其它机场；**单击小地图**可设定自定义航点(WPT)，
航线、方位、距离随之更新；**双击**清除自定义航点回到默认目标机场。

纯 2D canvas 实现，无额外依赖；切换机场时航迹与航点自动清空。
